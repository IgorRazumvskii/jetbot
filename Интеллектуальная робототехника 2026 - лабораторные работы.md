# **Лабораторная работа 1\. Настройка программ на ноутбуке с ОС Ubuntu**

**Краткое содержание:**

* Установка и запуск ROS на ноутбуке.  
* Импорт модели робота в симулятор Gazebo  
* Установка и настройка Visual Studio Code

**Дополнительные материалы:**

* Интеграция нейросетевых модулей в ROS: [https\://youtu.be/-Q4iLFDTpSE](https://youtu.be/-Q4iLFDTpSE) 

**Описание используемого оборудования и программного обеспечения**:

Данная лабораторная работа является вводной и выполняется в рамках домашнего задания на ноутбуках. Эти ноутбуки в дальнейшем будут использоваться на лабораторных работах в том числе для удаленной работы с учебными роботами JetBot. Один робот выдается на учебную бригаду (2-3 человека). Студенты группы должны самостоятельно разделиться на бригады так, чтобы в каждой бригаде был хотя бы один ноутбук с операционной системой Linux (желательно \- Ubuntu 20.04+). Если на ноутбуке стоит другая ОС, желательно поставить Ubuntu как вторую систему. 

# **Лабораторная работа 2\. Знакомство с роботом реальным и виртуальным. Работа с интерфейсами коммуникации, сенсорами, актуаторами и устройствами вывода через ROS.**

**Виртуальный робот в симуляторе Gazebo**

1. **Установка ROS2 Humble \+ Gazebo на ноутбук:** 

если не установлен ROS2 нативно, проще всего его установить в докере:  
docker pull osrf/ros:humble-desktop-full

Далее нужно создать ROS Workspace (папка ros2\_ws, в ней в папке src будут все наши ROS2-пакеты)

2. **Запуск Gazebo**

В ROS2 Gazebo запускается командой ign:  
ign gazebo \-v 4 \-r visualize\_lidar.sdf  
Откроется окошко с газебовским миром и моделькой робота из шариков и параллелепипедов.

3. **Запуск Gazebo с моделькой джетбота на складе**

Сначала просто запустим Gazebo:  
ign gazebo \-v 4 \-r  
Если долго не запускается – можно закрыть и запустить еще раз, вполне возможно что запустится. Далее в открывшемся окошке выбираем “Tugbot in warehouse” – загрузится среда с моделью склада и моделью робота Tugbot на складе.  
Вместо робота Tugbot хотелось бы видеть модельку нашего Jetbot-a.  
Она есть в [репозитории](https://github.com/KirillMouraviev/jetbot_ros_gazebo). Репозиторий нужно склонировать и собрать в воркспейсе как ROS2 пакет. Моделька робота имеет лидар и камеру, но топики с них сразу не видны в ROS \- нужен ros\_gz\_bridge. Свяжем ROS и Gazebo согласно [туториалу](https://docs.ros.org/en/humble/Tutorials/Advanced/Simulators/Gazebo/Gazebo.html).

Затем нужно открыть файл  /root/.ignition/fuel/fuel.gazebosim.org/openrobotics/worlds/tugbot\\ in\\ warehouse/2/tugbot\_warehouse.sdf (например, с помощью расширения Docker-a для vscode) и вместо модельки Tugbot-a поставить туда ссылку на модельку Jetbot-a.

После встраивания модельки джетбота запустим Gazebo со средой Tugbot in warehouse:   
ign gazebo \-v 4 \-r /root/.ignition/fuel/fuel.gazebosim.org/openrobotics/worlds/tugbot\\ in\\ warehouse/2/tugbot\_warehouse.sdf

**Реальный Jetbot**  
**0\. Подключение к роботу с ноутбука**

Есть два способа подключения:

1. Через USB-интерфейс (кабель для подключения есть в коробке от робота). ip-адрес робота при подключении по USB 192.168.55.1.  
2. Через Wi-Fi, если робот и компьютер подключены к одной сети. Если робот подключен к какой-либо сети, ip-адрес робота отображается на маленьком дисплее в задней части робота.

В обоих случаях, узнав ip-адрес робота, подключаемся к нему из терминала в ноутбуке через ssh:

ssh jetbot@\<ip\_address\>

Пароль от всех роботов: jetbot

Для подключения робота к WiFi-сети через терминал можно воспользоваться утилитой nmtui:

\$ sudo nmtui

Затем нужно выбрать Activate a Connection и выбрать сеть и ввести ключ доступа.

У роботов есть проблемы с датой, установим правильную дату и время вручную на роботе вот такой командой, чтобы дальше работала установка пакетов в докере:  
sudo date \--set="2025-09-15 13:42:00" (поменять на актуальные дату и время)  
cd jetbot\_ros2\_mipt  
**Чтобы роботы не конфликтовали друг с другом, в файле docker-compose.yml устанавливаем ROS\_DOMAIN\_ID, равный номеру робота.**  
Далее запускаем контейнер с ROS2 и всеми необходимыми драйверами (образ уже есть на роботе собранный):  
docker compose run \-it jetbot\_educational bash

1. **Запуск драйверов робота**

В контейнере чистим старую сборку и собираем заново workspace:  
rm \-rf build install log  
colcon build  
Затем устанавилваем переменные окружения командой source:  
source install/local\_setup.bash  
Далее запускаем лаунчфайл для драйверов всех сенсоров робота и моторов:  
ros2 launch jetbot\_bringup activate\_all\_drivers[.launch.py](http://.launch.py)  
Теперь, подключившись к роботу в другом терминале (с помощью команды docker exec …), можно увидеть топики лидара, камеры и моторов:  
ros2 topic list

2. **Визуализация сенсоров робота в RViz на ноутбуке**

В запущенном на ноутбуке контейнере устанавливаем переменные окружения для дисплея и для ROS2 и запускаем RViz (команда rviz2)  
source /opt/ros/humble/setup.bash  
export DISPLAY=:1 (или export DISPLAY=:0, если не сработало)  
export ROS\_DOMAIN\_ID=\<jetbot\_id\>  
rviz2

3. **Управление роботом с клавиатуры ноутбука**

Подключаемся к контейнеру, запущенному на ноутбуке (через docker exec), и там доустанавливаем пакет teleop\_twist\_keyboard и запускаем его:  
apt-get update  
apt-get install ros-humble-teleop-twist-keyboard  
ros2 run teleop\_twist\_keyboard teleop\_twist\_keyboard

4. **Установка драйвера для камеры**

На джетботе стоит Pi Camera, поэтому нужно будет установить драйвер для нее (в контейнере):  
cd src  
git clone https\://github.com/rpapallas/pi\_camera\_ros  
cd ..  
colcon build  
Проверим, что она работает:  
ros2 run pi\_camera publish\_compressed  
Драйвер камеры публикует только сжатые изображения, чтобы публиковать несжатые, модифицируем код publish\_compressed.py, создав новый файл publish\_raw.py.  
Добавим строчку для создания ROS-узла по скрипту publish\_raw.py в файл [setup.py](http://setup.py):  
entry\_points={  
    'console\_scripts': \[  
     'publish\_compressed \= pi\_camera.publish\_compressed:main',  
      ‘publish\_raw \= pi\_camera.publish\_raw:main’,  
    'view\_compressed \= pi\_camera.view\_compressed:main',  
    \],  
},  
И пересоберем ros2\_ws командой colcon build

**Рабочий пайплайн GStreamer для publish\_raw:**  
pipeline \= \[  
        	'gst-launch-1.0', '-q',  
        	'nvarguscamerasrc', f'sensor-id={self.sensor\_id}',  
        	'\!', (f'video/x-raw(memory:NVMM),width={self.width},'  
         	f'height={self.height},format=NV12,framerate={self.fps}/1'),  
        	'\!', 'nvvidconv',  
        	'\!', 'video/x-raw,format=BGRx',  
        	'\!', 'videoconvert',  
        	'\!', 'video/x-raw,format=BGR',  
        	'\!', 'filesink', 'location=/dev/stdout',  
    	\]

**Порядок запуска ROS2-драйвера камеры в Docker-контейнере**

1\. Проверить работу камеры на хосте, вне контейнера

\`\`\`bash  
gst-launch-1.0 \-q \\  
  nvarguscamerasrc num-buffers=1 sensor-id=0 \\  
  \! 'video/x-raw(memory:NVMM),width=1280,height=720,format=NV12,framerate=30/1' \\  
  \! nvvidconv \\  
  \! 'video/x-raw,format=BGRx' \\  
  \! fakesink  
\`\`\`

Код возврата должен быть \`0\`:

\`\`\`bash  
echo \$?  
\`\`\`

2\. Пересоздать контейнер jetbot\_educational, если он уже есть на роботе. Обычного \`restart\` недостаточно, потому что новые mounts, environment и группы применяются только при создании:

\`\`\`bash  
cd \~/IntelligentRoboticsOld/jetbot\_ros2\_mipt  
docker compose config \-q  
docker compose up \-d \--force-recreate  
\`\`\`

**\*\*Команды ниже выполняются внутри контейнера\*\***

3\. Проверить NVIDIA-плагины внутри контейнера:

\`\`\`bash  
docker exec jetbot\_ros2\_mipt-jetbot\_educational-1 bash \-lc '  
id  
test \-S /tmp/argus\_socket  
gst-inspect-1.0 nvarguscamerasrc \>/dev/null  
gst-inspect-1.0 nvvidconv \>/dev/null  
echo CAMERA\_RUNTIME\_OK  
'  
\`\`\`

В выводе \`id\` должна быть группа \`video\`, а в конце — \`CAMERA\_RUNTIME\_OK\`.

4\. Пересобрать workspace (достаточно только пакет камеры):

\`\`\`bash  
docker exec jetbot\_ros2\_mipt-jetbot\_educational-1 bash \-lc '  
source /opt/ros/humble/install/setup.bash  
cd /home/app/ros2\_ws  
colcon build \\  
  \--symlink-install \\  
  \--packages-select pi\_camera \\  
  \--event-handlers console\_direct+  
'  
\`\`\`

5\. Запустить драйвер:

\`\`\`bash  
docker exec \-it jetbot\_ros2\_mipt-jetbot\_educational-1 bash  
source /opt/ros/humble/install/setup.bash  
source /home/app/ros2\_ws/install/setup.bash  
ros2 run pi\_camera publish\_raw  
\`\`\`

6\. В другом терминале проверить публикацию:

\`\`\`bash  
docker exec \-it jetbot\_ros2\_mipt-jetbot\_educational-1 bash \-lc '  
source /opt/ros/humble/install/setup.bash  
source /home/app/ros2\_ws/install/setup.bash  
ros2 topic hz /camera/image/raw  
'  
\`\`\`

Ожидается примерно 28–30 FPS.
